# WinUI 3 高 DPI 自动化截图与导航踩坑

## 现象

在 125% DPI 下用 DPI-unaware PowerShell 调用 `GetWindowRect` 和 `PrintWindow`，1680×1000 DIP 的 WinUI 窗口只得到 1680×1000 像素画布，右侧内容看似被裁切；实际窗口物理尺寸是 2100×1250。

直接向 WinUI 顶层窗口发送鼠标消息也不可靠：导航项由内部 InputSite 承载，顶层 `WM_LBUTTONDOWN` 可能不命中真实控件，后续 `PrintWindow` 还可能得到短暂空白帧。

## 稳定做法

1. 用 Windows UI Automation 按可访问名称查找内部 TextBlock，再取父级 `ListViewItem`。
2. 对父级使用 `SelectionItemPattern.Select()`，不要对 TextBlock 调用 SelectionItemPattern。
3. 截图进程先调用 `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)`。
4. 再读取真实窗口矩形并调用 `PrintWindow(PW_RENDERFULLCONTENT)`；1680×1000 DIP 在 125% DPI 下应得到 2100×1250 px。
5. 若窗口被其他应用遮挡，可短暂使用 `SetWindowPos(HWND_TOPMOST)`，截图后立即恢复 `HWND_NOTOPMOST`。

## 判定原则

看到右侧裁切时先核对截图进程 DPI 上下文和最终像素尺寸，不要立即修改 XAML。只有在 DPI-aware 完整窗口图仍发生溢出时，才视为产品布局缺陷。

## 复发补充：最小化窗口和空白帧

Phase 3 验收时，`MainWindowHandle` 对应窗口处于最小化状态，`GetWindowRect` 只返回 199×34。调用 `ShowWindow(SW_RESTORE)` 后虽然恢复到 1680×1000，但 `PrintWindow(PW_RENDERFULLCONTENT)` 仍可能只得到白色帧，`CopyFromScreen` 在合成器不可见时也可能只截到桌面背景。

处理顺序：

1. 截图前先检查宽高，低于产品窗口下限时先恢复窗口；
2. 截图后必须实际查看图片，纯白或纯色帧不得作为验收证据；
3. 图像捕获不可用时，使用 UI Automation 核对关键文本的 `BoundingRectangle`、`IsOffscreen` 和可见滚动条数量；
4. 删除无效截图，不在验收文档中引用。

> [!warning]
> `PrintWindow` 返回 `true` 只代表调用成功，不代表 WinUI 合成内容已经进入位图。
