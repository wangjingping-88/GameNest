# GameNest 本地扫描调试心得

## 先把扫描拆成可观测步骤

扫描链路按“来源适配 → 证据评分 → 同目录归并 → 持久化 → 人工确认”拆开。每个候选保存来源、分数和证据，误判时可以定位是哪条规则造成，而不是把整个扫描器当成黑盒。

## 文件系统测试使用临时目录

- Steam、快捷方式和通用 EXE 适配器分别测试，不依赖开发机真实游戏库。
- 用临时目录构造清单、可执行文件和缺盘路径，测试结束自动回收。
- 重解析点、无权限目录和卷离线应按目录降级，不能让一次异常中断整个扫描。

## 并发与可取消性

- 通用 EXE 遍历使用有界工作队列，限制并发数，避免一次性创建大量任务。
- 暂停发生在目录边界，取消令牌贯穿适配器、仓储和导入服务。
- UI 只消费进度和状态，不在 code-behind 中执行扫描或数据库操作。

## 增量与盘符变化

增量扫描以稳定卷标识、路径、大小和修改时间组成文件指纹。盘符变化后先按卷标识重绑定扫描根、游戏路径和候选路径，再进行增量比对；只保存盘符会把同一块移动硬盘误判为新来源。

> [!tip]
> 遇到“扫描结果突然为空”时，优先检查 ScanRun 错误摘要、ScanRoot 在线状态和排除目录，再检查评分阈值；不要先放宽所有规则。
