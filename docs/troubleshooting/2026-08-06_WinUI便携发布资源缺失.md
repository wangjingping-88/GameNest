# WinUI 3 unpackaged 便携发布缺少 XBF 与 PRI 的定位方法

## 现象

目录型 `dotnet publish` 成功、主 EXE 能启动进程，但主窗口加载时记录 `XamlParseException: XAML parsing failed`，数据库没有初始化。相同配置的 `bin\Release` 程序可以正常启动。

## 定位顺序

1. 用独立的 `GAMENEST_DATA_ROOT` 启动发布包，避免读写真实用户库。
2. 检查隔离目录日志，确认异常发生在 `MainWindow.InitializeComponent()`。
3. 对比 `bin\Release` 与 publish 目录的顶层文件名和 SHA-256。
4. 本次确认 publish 目录漏了应用自身的 `App.xbf`、`MainWindow.xbf`、`GameNest.App.pri`，而 DLL 内容一致。

## 修复

发布脚本在 `dotnet publish` 后，从同一次 Release 构建输出显式复制三项 WinUI 资源，并把它们加入发布包必需文件审计。缺任何一项都立即失败，不继续生成 ZIP。

```powershell
$resources = @('App.xbf', 'MainWindow.xbf', 'GameNest.App.pri')
foreach ($resource in $resources) {
    Copy-Item -LiteralPath (Join-Path $appBuildOutput $resource) -Destination $packageRoot
}
```

## 验证标准

- 发布包内容审计通过；
- 隔离数据目录内成功创建 `data\gamenest.db`；
- 启动后台自动备份创建 `backups\gamenest-auto-*.db`；
- 主窗口可通过正常关闭请求退出，不使用强制结束。

不要通过忽略 `XamlParseException`、复制整个开发输出目录或放宽审计来掩盖资源缺失。发布目录应只补齐明确需要的运行时资源。
