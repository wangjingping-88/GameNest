# PresentMon 与 ETW 工具的能力分层检测

调试依赖 ETW 的外部工具时，不要把“EXE 存在且可启动”当成能力可用。推荐固定检查顺序：

1. **供应链层**：固定版本、SHA-256、Authenticode 签名和许可证；
2. **进程层**：能否以目标普通用户身份启动，标准输出/错误是否可读；
3. **系统能力层**：创建一个 1 秒、无持久输出的最小真实 ETW 会话；
4. **目标层**：对可控 PID 是否出现期望的呈现事件；
5. **降级层**：权限、驱动或 API 不支持时，是否只禁用相关指标。

能力检测必须设置超时，并使用唯一会话名，结束后检查是否有残留会话或辅助进程。错误状态至少区分文件缺失/哈希异常、权限不足、超时、目标无事件，避免把所有失败都显示成“未安装”。

对产品代码，最重要的原则是：检测与实际运行使用同一权限、同一固定二进制和同一关键参数；否则“检测通过、运行失败”会成为稳定复现的误报。
