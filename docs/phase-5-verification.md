## 已实现

### 图片与手工导入

- `IImageAssetCache` 统一处理图标和封面，缓存文件使用 SHA-256 内容哈希、资产类型和请求尺寸命名。
- 图标请求 256 像素，封面请求 900 像素；UI 额外设置解码宽度，避免在虚拟化卡片中解码原始大图。
- 支持手工选择 PNG、JPG、JPEG、BMP、WebP 封面，也可发现安装目录顶层的常见封面文件名。
- 手工移除封面后保留保护标记，不会再次自动匹配。

### 元数据边界

- `IMetadataProvider` 定义可取消的搜索接口；单个提供者异常被转为独立失败结果。
- 元数据应用记录提供者、来源 ID、来源名称和更新时间。
- `UserEditedFields` 精确保护名称、简介、参数、工作目录和封面。
- `MetadataRevisions` 保存应用前快照，错误匹配可撤销；撤销不影响游戏启动、收藏、时长或本地封面。
- 默认运行时未注册在线提供者，因此断网或外部 API 故障不影响游戏库和启动。

### Fluent Air 与可访问性

- 游戏卡片使用 2:3 外形和 `UniformToFill` 封面；无封面时显示本地图标和低对比度占位层。
- 首页有游戏时 Hero 展示最近启动或最近添加的游戏，无数据时保留已验收的本地优先引导。
- 详情面板展示纵向封面、来源归因、运行状态、会话时长和封面操作。
- 初始化期间显示骨架屏，加载失败提供明确说明和“重新加载”。
- 新增封面图片、按钮、加载状态和错误重试的辅助功能名称与帮助文本。
- `ItemsWrapGrid` 继续承担卡片虚拟化；搜索结果集合改为一次替换，避免 1000 次逐项通知。

## 已知风险与延期项

- 本机没有真实游戏，封面流程和 1000 条 UI 滚动仍需人工视觉/交互验收；自动化已覆盖模型、缓存、SQLite 和搜索预算。
- 正式在线提供者未接入；这是产品计划允许的“完整手工导入流程”分支。未来接入前需单独确认服务条款、隐私、匹配质量和密钥存储。
- Phase 4 的 DX11、DX12、OpenGL 真实 FPS 因普通权限 ETW 能力限制，按用户决定延期到家中环境补测。
