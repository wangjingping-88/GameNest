# GameNest 架构决策记录

> 适用范围：Phase 0 至 Phase 6  
> 日期：2026-08-06

## ADR-001：固定 .NET 10 与 Windows App SDK Stable

- 状态：已采用。
- 决策：使用 .NET SDK 10.0.302、C# 14、Windows App SDK 2.3.1 Stable。
- 原因：与产品方案一致，避免 Preview/Experimental API 和构建漂移。
- 落地：`global.json` 固定 SDK；`Directory.Packages.props` 集中固定直接包；每个项目提交 `packages.lock.json`。

## ADR-002：分层依赖方向

依赖只允许由外向内：

```text
GameNest.App ─────────────> GameNest.Application ────────> GameNest.Domain
       │                             ▲
       └────> GameNest.Infrastructure ─────> GameNest.Telemetry ─────┘
                                                     ▲
GameNest.Overlay ─────────────────────────────────────┘
```

- Domain 不引用 WinUI、SQLite、文件系统或网络。
- Application 定义游戏库、扫描、运行、遥测、覆盖层和设置端口，不了解 Win32/SQLite 实现。
- Infrastructure 实现 SQLite、Windows 服务、日志，并在组合根注册 Telemetry 实现。
- ViewModel 只调用 Application 接口，不直接访问数据库。
- Overlay 只引用 Telemetry 的版本化管道协议，不引用 App、Infrastructure 或数据库。

## ADR-003：unpackaged、self-contained x64

- 状态：已采用。
- 决策：开发阶段主程序和 Overlay 使用 unpackaged、self-contained x64。
- 原因：减少目标机运行时依赖，符合产品方案的开发阶段策略。
- 影响：Release 输出目录体积较大；安装包和便携版在 Phase 6 再评估。

## ADR-004：SQLite 显式迁移与 WAL

- 状态：已采用。
- 决策：启动时通过 `IApplicationDataInitializer.InitializeAsync` 执行显式、可重复的迁移。
- 初始迁移：`001_initial`，创建产品方案中的核心表和 `AppSettings`。
- 可靠性：迁移在事务中执行；成功后写入 `SchemaMigrations`；SQLite 启用 WAL、外键和 busy timeout。
- 线程约束：目录创建放到后台任务，连接和命令使用异步 API，UI 不直接执行本地 I/O。

## ADR-005：后台滚动文件日志

- 状态：已采用。
- 决策：自定义 `ILoggerProvider` 使用有界 Channel 接收日志，并由后台任务异步写文件。
- 原因：避免 UI 线程文件写入，同时不额外引入日志包。
- 边界：队列满时丢弃最旧日志；单文件达到 5 MB 后按序号滚动；日志自身失败不使主程序崩溃。

## ADR-006：主题由 ViewModel 协调、界面层应用

- 状态：已采用。
- 决策：Application 层使用 `ThemePreference` 表达浅色、深色和跟随系统；Infrastructure 异步保存；XAML 转换为 `ElementTheme`。
- 原因：主题偏好可测试，ViewModel 不依赖 SQLite，code-behind 不承载业务。
- 默认值：首次启动为浅色。

## ADR-007：Phase 0 严格留白后续能力

- 状态：已采用。
- Telemetry 只提供程序集标记，不接入 PresentMon、PDH 或进程 API。
- Overlay 只提供立即退出的独立进程入口，不创建覆盖层窗口或 IPC。
- 未实现扫描适配器、在线元数据提供者、启动/停止服务和进程强杀。
- UI 使用真实空状态，不使用虚构游戏、封面、运行时长或性能数据。

## 视觉决策：B｜Fluent Air

- 色彩：暖灰画布 `#F5F7FA`、白色表面、细边框 `#E4E9F0`、唯一主强调蓝 `#2688F4`。
- 字体：标题使用 Segoe UI Variable Display，正文使用 Segoe UI Variable Text。
- 布局：固定左导航、中央 Hero/内容、右侧会话与外观状态栏，保持参考图的三栏信息层级。
- 标志性元素：Hero 中只保留一组轻透的蓝色“气流轨迹”，表达把散落游戏汇聚到本地入口；其余装饰保持克制。
- 深色主题：使用独立深色令牌，不做简单反色。

## ADR-008：Phase 1 游戏聚合由应用服务统一编排

- 状态：已采用。
- 决策：`Game` 聚合游戏元数据、默认 `LaunchProfile` 与本地图标 `GameAsset`；`GameLibraryService` 统一编排添加、查询、编辑、收藏、移除、图标刷新和启动。
- 边界：ViewModel 只调用 Application 层用例，不直接访问 SQLite、文件系统、快捷方式 COM 或 `System.Diagnostics.Process`。
- 原因：保持 WinUI 展示层可替换、业务规则可单测，并为后续扫描结果复用同一持久化入口预留空间。

## ADR-009：手工导入先规范化本地启动信息

- 状态：已采用。
- 决策：`.exe` 直接规范化为绝对路径；`.lnk` 在后台通过 Windows Shell Link COM 读取目标、参数、工作目录和图标来源，再保存解析后的默认启动配置。
- 约束：Phase 1 只处理用户主动选择的文件，不枚举目录、不读取游戏平台清单、不触发磁盘扫描。
- 可靠性：添加前按规范化后的可执行路径执行不区分大小写的重复检查；所有文件检查和快捷方式解析均异步或在后台线程执行。

## ADR-010：图标提取与游戏记录入库解耦

- 状态：已采用。
- 决策：添加流程只等待文件检查、重复检查与 SQLite 事务；记录入库后立即返回 UI，图标提取作为可观察异常的后台任务补齐。
- 一致性：后台任务只调用 `SetIconAsync` 更新 `GameAssets`，不使用添加时的旧聚合覆盖用户随后发生的编辑、收藏或最近启动状态。
- 降级：图标提取失败时保留占位封面并记录不含完整隐私路径的诊断日志，不阻断添加。

## ADR-011：Phase 1 只跟踪直接 PID

- 状态：已由 ADR-019 取代；保留为 Phase 1 历史决策。
- 决策：启动成功后保存 `Process.Start` 返回的直接 PID，并通过退出事件维护“启动中 / 运行中 / 未运行”状态。
- 竞态处理：在注册退出回调前缓存 PID，避免极短生命周期进程先退出并释放 `Process` 后再次读取 PID；退出后允许重新启动。
- 明确不做：不执行启动前后进程快照、不接管启动器派生的子进程、不提供停止或强杀。这些能力不得在 Phase 1 静默扩张。

## ADR-012：平台交互保留在薄 code-behind 中

- 状态：已采用。
- 决策：WinUI `FileOpenPicker`、`ContentDialog` 和窗口句柄初始化留在 `MainWindow.xaml.cs`；验证、持久化、过滤、收藏、启动等核心业务全部由 ViewModel 与 Application 层完成。
- 原因：文件选择器和对话框需要 `XamlRoot`/窗口句柄，但不应因此把业务规则写入 XAML code-behind。

## ADR-013：保留用户确认的 1680×1000 原生窗口下限并做高度响应

- 状态：已采用。
- 冲突：产品文档建议最低窗口尺寸 `1000×680` DIP；Phase 0 视觉验收中，用户明确指定以 1680×1000 物理窗口作为默认和缩小下限。
- 决策：继续保留用户确认的原生窗口下限，不回退该行为；同时压缩首页固定高度、间距和空状态密度，使非最大化窗口及常见 DPI 缩放下内容不被裁切且不出现滚动条。
- 风险：工作区物理尺寸小于 1680×1000 的显示器仍可能被系统工作区限制，需在后续 DPI 矩阵中继续验证。

## ADR-014：统一扫描适配器与集中评分归并

- 状态：已采用。
- 决策：Steam、Windows 快捷方式和通用 EXE 均实现 `IGameSourceAdapter`，统一输出 `DiscoveredGame`；`GameCandidateScorer` 负责分数和解释证据，`GameCandidateGrouper` 负责同目录主程序选择。
- 原因：平台发现方式可以扩展，但置信度阈值、负面文件名和目录归并不能在适配器间漂移。
- 阈值：70 分以上为高置信，40 至 69 分待确认，40 分以下默认忽略；卸载器、安装器、更新器和崩溃上报器按产品规则显著降权。

## ADR-015：有界后台扫描与协作式暂停/取消

- 状态：已采用。
- 决策：通用目录扫描使用 3 个后台工作线程和 Channel 派发目录；每个目录和候选检查前等待 `IScanPauseToken` 并检查 `CancellationToken`。
- 容错：单目录的无权限、I/O、路径过长或磁盘断开异常只记录并跳过；重解析点不入队，已访问绝对路径去重，避免符号链接循环。
- UI：ViewModel 只接收进度并发出暂停、继续、取消命令，不同步枚举磁盘。

## ADR-016：轻量增量指纹与显式 Phase 2 迁移

- 状态：已采用。
- 决策：使用规范化路径、文件大小和最后修改时间生成 SHA-256 轻量指纹；指纹未变化时复用上次候选评分和解释，不重复读取版本元数据。
- 存储：新增 `002_phase2_scan`，为 `ScanRoots` 增加在线状态，并创建 `ScanRuns`、`ScanCandidates`、`ScanExclusions`；不重建 `001_initial` 或清空 Phase 1 数据。
- 检查点：扫描完成后按根目录更新 `LastScanUtc` 和 `LastCheckpoint`。

## ADR-017：卷标识驱动离线保留与盘符重绑定

- 状态：已采用。
- 决策：Windows 卷 GUID 作为稳定标识，同时保存当前路径和卷内相对路径；启动和扫描前枚举在线卷并重建当前路径。
- 离线行为：卷不可用时游戏标记为 `VolumeOffline`，不删除游戏、候选或用户编辑；重新接入后恢复 `Available` 并重写受该卷管理的路径前缀。

## ADR-018：扫描确认仍由应用服务入库

- 状态：已采用。
- 决策：扫描页只管理候选选择；确认后由 `GameScanService` 调用 `GameLibraryService.ImportCandidateAsync`，复用 Phase 1 的游戏聚合和 SQLite 仓储。
- 边界：文件夹选择器保留在薄 code-behind；扫描、评分、排除、确认、持久化和卷重绑定均位于 Application/Infrastructure。
- 明确不做：Phase 2 不实现在线元数据、进程快照、子进程接管、停止/强杀、遥测或覆盖层。

## ADR-019：启动前后快照与证据化进程接管

- 状态：已采用。
- 决策：启动前记录系统进程快照，启动后持续读取 PID、父 PID、进程名、可执行路径和启动时间；入口进程、其派生链、精确路径和用户配置的预期进程名可形成已确认身份。
- launcher：入口进程退出后保留 4 秒接管窗口；派生进程仍在运行时会话不结束，主 PID 切换到实际游戏进程。
- 降级：只能命中安装目录的进程标记为“可能”，可以显示运行状态，但不产生停止权限。

## ADR-020：停止操作以身份确认和正常关闭优先

- 状态：已采用。
- 决策：停止前同时要求“已确认”置信度和可读取的进程启动时间；控制器再次比对 PID 与启动时间，避免 PID 复用误伤。
- 流程：先调用 `CloseMainWindow`，按 `GracefulStopTimeoutSeconds` 等待；无主窗口或超时后返回 `ConfirmationRequired`，由 WinUI 显示二次确认，再逐个结束已确认 PID。
- 安全边界：未确认进程不显示停止入口；不结束整棵未知进程树，不提权，不绕过反作弊或系统访问控制。

## ADR-021：会话结束与累计时长原子结算

- 状态：已采用。
- 决策：`PlaySessions` 保存开始/结束、退出类型和全部跟踪 PID；会话结束和 `Games.TotalPlaySeconds` 更新位于同一 SQLite 事务。
- 迁移：`003_phase3_runtime` 为每个游戏增加唯一活动会话约束和历史查询索引，不重建旧表。
- 恢复：正常关闭 GameNest 不结束游戏，只以 `ApplicationClosed` 结算跟踪；下次启动将遗留活动会话标记为 `TrackingLost`，避免数据库永久卡在活动状态。

## ADR-022：二次强制确认属于界面桥接

- 状态：已采用。
- 决策：ViewModel 发起正常停止并接收 `GameStopResult`；只有 `ConfirmationRequired` 时，薄 code-behind 使用 `ContentDialog` 展示剩余 PID 与存档风险，再把明确确认传回应用服务。
- 边界：进程匹配、等待、身份校验、强制结束和会话结算均不在 code-behind 中执行。

## ADR-023：PresentMon 固定版本与真实能力探测

- 状态：已采用。
- 决策：FPS 仅使用 PresentMon 2.5.1 standalone x64；启动前校验 SHA-256，并通过 1 秒无 CSV ETW 会话验证普通权限能力。
- 降级：缺失、哈希不符、权限拒绝、超时或无呈现事件均只影响 FPS，返回明确状态而非假值。
- 权限：主程序不自动提权、不修改 `Performance Log Users`，也不静默以管理员身份重启。

## ADR-024：四项遥测按能力独立降级

- 状态：已采用。
- 决策：FPS、进程组 CPU、GPU Engine、进程组私有内存分别保存值、状态和诊断；500 ms 发布快照，CPU/GPU/RAM 每 1000 ms 更新。
- 口径：CPU 按逻辑处理器归一化；RAM 对已确认进程求和；GPU 对同引擎求和后选择最繁忙引擎，限制为 0 至 100%。
- 容错：单项采样异常不终止其他采样循环；目标 PID 只来自 Phase 3 已确认进程组。

## ADR-025：外部独立覆盖层与受限命名管道

- 状态：已采用。
- 决策：`GameNest.Overlay` 是独立 Win32 进程，使用 `TOPMOST | TRANSPARENT | TOOLWINDOW | LAYERED | NOACTIVATE` 的无边框窗口。
- IPC：当前用户命名管道只接收带版本、最大 64 KB 的帧/状态/隐藏/退出消息，不接受路径、数据库访问或任意命令执行。
- 安全边界：不注入 DLL、不 Hook DirectX/Vulkan/OpenGL、不修改游戏内存；覆盖层异常不结束游戏或主程序。

## ADR-026：250 ms 目标窗口跟踪与前台隐藏

- 状态：已采用。
- 决策：只枚举已确认 PID 的可见、非工具、非 cloaked 顶层窗口，以前台、主 PID 和客户区面积评分。
- 坐标：使用客户区屏幕物理坐标和窗口 DPI；分辨率、位置、DPI 或显示器变化时重新下发覆盖层帧。
- 行为：最小化、失去前台或窗口暂不可定位时隐藏；检测到全屏覆盖时说明独占全屏边界，不转向注入。

## ADR-027：OverlayProfile 复用初始表并支持按游戏覆盖

- 状态：已采用。
- 决策：复用 `001_initial` 已创建的 `OverlayProfiles`，不增加破坏性迁移；保留一个全局配置，并允许单游戏配置覆盖。
- 校验：位置、四档缩放、50% 至 95% 透明度和带修饰键的全局快捷键均在 Domain/Application 层验证。
- 展示：设置页预览明确标注示例值；单游戏对话框只做展示桥接，核心保存规则不进入 code-behind。

## ADR-028：可控渲染程序代替开发机真实游戏

- 状态：已采用。
- 决策：提供最小 DX11、DX12、OpenGL 窗口程序和隔离 Phase 4 Harness，不扫描、不写用户游戏库。
- 验证：Harness 使用正式窗口定位、遥测和覆盖层实现，测量窗口化/无边框、焦点、穿透、重定位和性能预算。
- 限制：本机 ETW 权限拒绝时保留“真实 FPS 未通过”的结论，不用生成值或 UI 示例冒充验收。

## ADR-029：Phase 5 采用完整手工元数据流程并保留提供者插槽

- 状态：已采用。
- 决策：Phase 5 交付可插拔 `IMetadataProvider`、来源归因、按提供者隔离失败、应用和撤销流程，但正式运行时不注册在线提供者；用户通过本地编辑和封面选择完成元数据补全。
- 原因：产品计划允许“至少一个在线提供者，或完整的手工导入流程”。当前没有已确认的 API 凭据、服务条款和匹配样本，手工流程能保持离线优先且不引入不可控网络依赖。
- 兼容：以后接入提供者时不改动游戏库核心；提供者失败只形成单独失败结果，不影响本地库、扫描或启动。

## ADR-030：手工字段保护与元数据修订不可混用

- 状态：已采用。
- 决策：`Games.UserEditedFields` 按 `Title`、`Description`、`Arguments`、`WorkingDirectory`、`Cover` 精确持久化；元数据应用只填充未被手工保护的标题和简介。
- 撤销：`004_phase5_metadata` 新增来源列和 `MetadataRevisions`，每次应用前保存上一个快照，撤销只恢复元数据字段和归因，不回滚收藏、启动配置、时长或封面。
- 封面：手工移除封面后仍保留 `Cover` 保护标记，防止后台本地发现再次替用户选图。

## ADR-031：图片按内容寻址并只向 UI 暴露缩略图

- 状态：已采用。
- 决策：图标和封面统一通过 `IImageAssetCache` 生成缩略图，按 SHA-256、资产类型和目标尺寸写入 `assets/cache`；相同内容复用同一路径。
- 尺寸：图标请求 256 像素，封面请求 900 像素；WinUI 再按控件尺寸设置解码宽度，不在卡片滚动时加载原始大图。
- 范围：缓存清理属于 Phase 6，本阶段只生成和引用缓存，不删除仍可能被用户记录引用的文件。

## ADR-032：Phase 6 采用目录型 x64 便携版

- 状态：已采用。
- 决策：发布 self-contained x64 目录和 ZIP，不启用单文件合并，也不在 0.1.0 引入安装器。
- 原因：产品计划允许“便携版或安装包”，目录型发布能保留 WinUI/Overlay/PresentMon 的清晰边界、启动速度和可诊断性。
- 卸载：包内脚本先明确询问是否保留数据库、备份、日志和封面缓存，默认保留，再删除带专用标记的便携目录。

## ADR-033：维护能力通过应用端口统一协调

- 状态：已采用。
- 决策：Application 定义 `IApplicationMaintenanceService`，Infrastructure 实现 SQLite 一致性备份、引用感知缓存清理和脱敏诊断压缩；ViewModel 只协调状态。
- 自动备份：启动后后台检查，24 小时最多一次，自动保留 7 份；失败不阻断游戏库启动。
- 清理边界：只检查受控图片缓存目录的直接子文件，仅删除数据库无引用项；不递归触碰游戏目录或用户原始封面。
- 诊断边界：用户主动选择目标目录；导出统计和脱敏日志，不导出数据库、游戏名称/路径或凭据。

## ADR-034：发布时绑定第三方工具并执行内容审计

- 状态：已采用。
- 决策：运行时只查找环境变量覆盖或包内相对路径，不包含开发机 PresentMon 绝对回退路径；发布脚本复制固定 2.5.1 并校验 SHA-256。
- 审计：发布包必须包含用户、隐私、兼容性和许可证文档；拒绝 PDB、私钥、测试 API Key、哈希漂移和开发机绝对路径。
- 限制：0.1.0 尚未代码签名；干净 Windows 虚拟机验收仍是对外发布前的人工门禁。

## ADR-035：公开 GitHub Release 是唯一应用更新源

- 状态：已采用。
- 决策：客户端固定请求公开仓库 `wangjingping-88/GameNest` 的 REST Release API，不接收用户自定义源、不携带 GitHub Token，只接受最新非草稿、非预发布且标签严格为 `vMAJOR.MINOR.PATCH` 的版本。
- 频率：自动检查由 SQLite 偏好保存，24 小时最多一次；响应正文和 ETag 缓存在 `%LOCALAPPDATA%\GameNest\updates`，请求通过信号量串行化。
- 降级：离线、超时、404、403/429、JSON 或资产异常只更新设置页状态，不影响数据库初始化、游戏库、启动或覆盖层。

## ADR-036：独立 ECDSA 更新信任链先于 ZIP 哈希

- 状态：已采用。
- 决策：Release 清单原始 UTF-8 字节使用 ECDSA P-256 / SHA-256 / IEEE P1363 签名；客户端按 `keyId` 选择内置 SPKI 公钥，验签通过后才信任清单中的资产名、大小、哈希、RID、最低系统版本和发布时间。
- 密钥：生产私钥只允许进入 GitHub Secret，不写入仓库、发布包或日志。当前 0.2.0 工作区未配置生产公钥，所以只能检查新版本并打开下载页，不能自动安装。
- 边界：下载仅允许 GitHub 与 GitHubusercontent 的 HTTPS 默认端口，限制 5 次重定向、1 GiB 压缩包、20,000 个 ZIP 条目和解压总量，并拒绝绝对路径及目录穿越。

## ADR-037：便携版升级使用同卷目录事务与健康确认

- 状态：已采用。
- 决策：下载、哈希和解压在本地更新目录异步完成；验证后把候选包复制到安装目录同一父目录，创建数据库手工备份，再由已验证包内的 `GameNest.App.exe --apply-update` 执行交换。
- 退出：升级器只等待旧主程序和 `GameNest.Overlay` 正常退出，超时即停止升级并保留旧版本，不调用 Kill、不请求管理员权限。
- 回滚：目标目录先改名为保留目录，候选目录再原子改名为目标目录；新版通过 `--complete-update` 隐藏初始化并写健康文件。启动、迁移或健康检查失败时恢复旧目录和更新前数据库备份。

## ADR-038：0.2.0 是在线升级 bootstrap

- 状态：已采用。
- 决策：程序集、文件和信息版本统一提升为 0.2.0。0.1.0 没有更新客户端，因此只能手动安装 0.2.0；配置生产公钥并完成 0.2.0 发布验收后，第一个端到端升级目标是 0.2.1。
- 发布门禁：tag 必须与 `Directory.Build.props` 一致，工作流固定 .NET 10.0.302、PresentMon 2.5.1 及哈希，完整测试后生成四项确定资产；缺少私钥 Secret、公钥变量或 keyId 时拒绝发布。
- 风险：清单签名保护升级链，不建立 Windows 发布者信誉；正式分发仍建议采购 Authenticode 代码签名证书。

## ADR-039：设置页采用二级分类目录与内容驱动详情

- 状态：已采用。
- 决策：设置页固定使用约 208 DIP 的二级分类目录，右侧一次只呈现一个详情分类；分类选择保存在 UI ViewModel 中，本次运行内重新进入设置页时保持选择，不扩展 Application 或 Domain 契约。
- 布局：默认及最小窗口保持 `1680×1000`；设置内容容器最大宽度约 1460 DIP，始终左对齐、顶部对齐。卡片按内容决定高度，不使用纵向 `*` 比例拉伸，最大化时不放大字体、内边距和按钮高度。
- 降级：默认有效视口不出现全局滚动条；高 DPI 或系统工作区强制压缩时，仅右侧详情区域允许自动滚动。应用更新的超长发布说明使用独立内部滚动区域。
- 品牌：浅色主题使用原始横向 Logo 与浅色底板；深色主题切换到确定性生成的透明底冷灰字标，边框和底板透明；高对比度主题使用系统窗口色。资源通过 `ThemeResource` 即时切换。
